# Key-Box Optimization Roadmap

本文档记录 Key-Box 后续打磨方向和优先级开发计划。它只作为产品与技术路线图，不替代现有架构设计文档，也不记录已经完成的历史变更。

## 1. 目标与原则

Key-Box 当前已经具备本地密码库的核心能力：注册、OTP 登录、密码条目加密保存、备份和恢复。下一阶段目标是把它从“可用的本地密码库”打磨成“更安全、更好用的本地密码管理器”。

核心原则：

- **安全地基优先**：先保证认证、密钥链、迁移和测试可靠，再扩展 UI 和便利功能。
- **老数据平滑迁移**：已有账号不能因为升级直接失效。老账号允许使用现有 OTP 登录一次，登录后强制设置登录密码。
- **GUI 优先**：新功能优先落在 GUI，CLI 暂时保持现状；底层服务设计应避免阻碍未来 CLI 补齐。
- **本地优先**：继续保持离线、本地数据库、本地配置 Salt 的使用模型，不引入云同步作为近期目标。
- **可分阶段发布**：每个优先级阶段都应能独立完成、测试和发布，避免一次性大改导致风险过高。

## 2. 优化建议归档

### 用户提出的优化方向

1. **登录安全增强**
   - 登录从当前 OTP-only 升级为“登录密码 + OTP”。
   - 注册时设置登录密码。
   - 登录时必须同时通过密码和动态验证码。
   - 支持修改登录密码和忘记密码后的重置流程。

2. **主页面与操作体验优化**
   - 当前密码库主页面展示简陋，需要更适合日常使用。
   - 添加和编辑弹框尺寸偏小，字段扩展后需要更清晰的表单布局。
   - 列表字段不完整，应展示更多账号信息和操作入口。

3. **账号分类功能**
   - 密码条目支持分类管理。
   - 主页面支持按分类筛选。
   - 分类应服务于快速定位账号，而不是只作为备注字段。

4. **个人信息和账号管理**
   - 增加个人信息/账号管理入口。
   - 支持修改登录密码。
   - 支持忘记密码后的改密码或重置流程。
   - 与现有密保问题、Key B、OTP 和密钥轮转机制保持一致。

### 补充建议

- **测试补齐**：增加注册、登录、重置、Salt 错误、备份恢复、加密数据不可见等核心测试。
- **字段扩展**：密码条目增加标题、URL、分类、备注、收藏、创建时间、更新时间等字段。
- **搜索筛选排序**：支持按标题、网站、账号、分类搜索；支持按最近更新、名称、分类排序。
- **密码生成器**：添加/编辑密码时支持生成强密码。
- **自动锁定**：应用闲置一段时间后自动锁定，重新进入需认证。
- **剪贴板保护**：复制密码后在指定时间内自动清空剪贴板。
- **数据库迁移机制**：新增 schema migration，避免后续手动改表。
- **GUI 拆分**：逐步拆分过大的 GUI 入口文件，降低后续维护成本。
- **安全中心**：集中展示 Salt 配置状态、备份提醒、OTP 状态、修改密码入口和安全设置。

## 3. 优先级开发计划

### P0：安全与迁移地基

目标：先补齐可靠性基础，为认证模型和数据库结构变化兜底。

- 增加核心测试覆盖：注册、登录、重置、Salt 错误、密码条目加密保存、备份恢复。
- 新增数据库迁移机制，维护当前 schema 版本。
- 设计登录密码存储方案：密码只保存 verifier/hash，不保存明文。
- 设计老账号迁移流程：老账号首次 OTP 登录后必须设置登录密码。
- 明确迁移失败、Salt 不匹配、老账号未设置密码等错误提示。

验收标准：

- `go test ./...` 可作为基础验证命令。
- 老账号数据不会在迁移前后丢失。
- 数据库中不出现登录密码明文。
- 迁移机制可重复运行，不重复破坏表结构。

### P1：密码 + OTP 登录

目标：把登录认证升级为“知道登录密码 + 持有 OTP”的双因素模型。

- 注册流程增加登录密码和确认密码输入。
- 登录流程增加密码输入，并在密码校验通过后继续校验 OTP。
- 个人信息页支持修改登录密码。
- 忘记密码流程通过密保答案恢复，并设置新的登录密码和 OTP 凭证。
- 老账号登录成功后进入强制设置密码流程，完成后再进入密码库。

验收标准：

- 新账号必须使用正确密码和正确 OTP 才能登录。
- 密码错误、OTP 错误、Salt 错误都不能登录。
- 修改登录密码后旧密码失效，密码库数据仍可正常解密。
- 老账号可以平滑升级到新登录模型。

### P2：密码库主页面重做

目标：让 GUI 主页面更适合真实密码管理场景。

- 主页面增加搜索框、分类筛选入口和排序方式。
- 列表展示更完整字段：标题、网站/URL、账号、分类、更新时间、收藏状态、操作按钮。
- 添加和编辑弹框改为更大的结构化表单。
- 密码字段默认隐藏，复制和显示操作分开。
- 空列表时显示添加入口和基础引导。

验收标准：

- 用户可以快速搜索和定位密码条目。
- 添加/编辑窗口在常见桌面尺寸下字段完整可见。
- 列表信息密度更高但不泄露明文密码。
- 编辑、删除、复制后列表状态能及时刷新。

### P3：账号分类与字段扩展

目标：把密码条目从简单三字段扩展为可管理的账号记录。

- 密码条目增加分类、标题、URL、备注、收藏、创建时间、更新时间。
- 提供分类管理能力：新增、重命名、删除或归档分类。
- 支持按分类筛选，并保留“全部”“收藏”“未分类”等默认视图。
- 备份和恢复格式保留新增字段。

验收标准：

- 旧密码条目迁移后自动进入“未分类”或默认分类。
- 分类变更不会影响密码解密。
- 备份恢复后分类和扩展字段完整保留。
- 搜索、筛选、编辑、删除与分类字段协同正常。

### P4：安全体验增强

目标：补齐密码管理器常见安全体验。

- 添加密码生成器：长度、大小写、数字、符号、排除易混字符。
- 添加自动锁定：空闲 N 分钟后清空会话状态并返回登录页。
- 添加剪贴板保护：复制密码后延迟清空剪贴板。
- 增加安全中心：Salt 状态、备份提醒、OTP 状态、修改密码、安全设置。
- 逐步拆分 GUI 文件，把登录、密码库、备份恢复、个人信息等 UI 分离。

验收标准：

- 生成器能生成符合选项的密码。
- 自动锁定后无法继续查看或复制密码。
- 剪贴板清理不会影响用户正在复制的新内容。
- 安全中心能清楚展示当前安全状态和关键操作入口。

## 4. 建议数据模型方向

后续实现时建议通过 migration 逐步扩展，而不是直接依赖 `CREATE TABLE IF NOT EXISTS` 的初始结构。

### users 表方向

建议新增与登录密码相关的字段：

- `password_salt`：登录密码派生盐。
- `password_verifier` 或 `password_hash`：登录密码校验材料。
- `password_kdf`：记录派生算法和参数版本。
- `requires_password_setup`：老账号是否需要首次登录后设置密码。
- `profile_updated_at`：个人信息更新时间。

约束：

- 不保存登录密码明文。
- 不把登录密码作为唯一的数据解密因子，避免忘记密码后无法通过密保流程恢复。
- 密码修改不应导致已保存的密码条目无法解密。

### vault 表方向

建议新增面向列表和分类的字段：

- `title`：条目显示名。
- `url`：网站或服务地址。
- `category` 或 `category_id`：分类。
- `favorite`：收藏状态。
- `created_at`：创建时间。
- `updated_at`：更新时间。

建议继续加密保存的数据：

- 账号名。
- 密码。
- 备注。
- 未来可能包含的二级验证码恢复码等敏感信息。

### 迁移表方向

新增 `schema_migrations` 表，记录已经应用的 migration 版本。每个 migration 应该满足：

- 可检测是否已经执行。
- 执行失败时返回明确错误。
- 不破坏已有用户和密码条目。

## 5. 测试与验收场景

后续实现每个阶段时，应至少覆盖以下测试场景：

- 注册新账号后必须使用密码 + OTP 才能登录。
- 老账号首次 OTP 登录后必须设置登录密码。
- Salt 错误、密码错误、OTP 错误都不能登录。
- 修改登录密码后旧密码失效，原密码库数据仍可解密。
- 忘记密码流程通过密保问题恢复，并生成新的登录凭证。
- 分类、搜索、编辑、删除不会破坏已加密密码数据。
- 备份恢复后分类和新增字段完整保留。
- 复制密码后剪贴板按设置自动清理。
- 自动锁定后会话 Key C 不再可用于查看密码。
- 数据库中不出现明文登录密码或明文密码条目。

基础验证命令：

```bash
go test ./...
```

## 6. 明确暂缓事项

以下能力有价值，但不建议放入近期路线图，避免影响核心体验打磨：

- 云同步。
- 浏览器插件。
- Touch ID / Face ID。
- YubiKey 等硬件密钥。
- 多语言国际化。
- 第三方密码管理器格式导入。

这些能力可以在 P0-P4 完成后单独设计。
